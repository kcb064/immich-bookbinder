# M6: free-form designer

Goal: the editor grows from "auto layout with tweaks" into a designer where any page (and the
cover) can be laid out by hand on the same page model: move and resize photo slots, add text
boxes, snap to guides, undo/redo, keyboard control. Templates become starting points, not
constraints. Nothing about rendering or the viewer changes because both draw from the same
`Page`/`SlotContent` model.

Read `CLAUDE.md` first. Expand this spec at the start of the milestone with the same sections as
M4 (existing seams, deliverables, judgement calls, acceptance criteria) after re-reading the code.

## Existing seams

- `Page`, `SlotContent`, `Crop` in `packages/shared/src/book.ts`; templates and `SlotSpec`
  (`x, y, w, h` in trim-width units, `role`, `aspect`, `bleed`) in `packages/layout/src/templates.ts`
  and `packages/shared/src/template.ts`.
- `PageView` (`packages/pages/src/PageView.tsx`) positions slots from the template geometry; the
  renderer and viewer reuse it.
- Pure editor operations with tests: `apps/web/src/lib/editor.ts` (`swapSlots`, `removePhoto`,
  `addPhoto`, `movePage`, `setTemplate`, `setCrop`, `setSlotText`, ...). Undo exists in
  `Editor.tsx` (M1); check its history model before extending it.
- Openers are fixed pages (`isFlexiblePage`); the cover model is from M4.

## Deliverables (outline)

1. **Geometry override on slots.** `SlotContent.frame?: { x, y, w, h, rotation?, z? }` in the
   same units as templates. When present, `PageView` uses it instead of the template slot. Pages
   with any override are tagged `custom: true` so re-layout leaves them alone.
2. **Text boxes.** `SlotContent` with `role: 'text'` created ad hoc (id `text-<uuid>`), styled
   from the theme (`packages/shared/src/theme.ts`), with size and alignment options.
3. **Direct manipulation.** Drag to move, handles to resize (aspect locked for photos unless a
   modifier is held), rotation handle, snapping to trim, safety, gutter, page centre and other
   slots' edges (snap lines rendered from `format` geometry), nudge with arrows (1/10 in, shift =
   1/2 in), z-order controls, duplicate, delete.
4. **Undo/redo** as a single history stack over `book.pages` + `book.cover` with coalescing of
   drags; keyboard shortcuts documented in a help overlay.
5. **Keyboard navigation** through spreads, slots and the photo tray; focus rings; all actions
   reachable without a mouse.
6. **Cover designer** reusing the same tools on the M4 cover sheet, with the spine drawn as a guide.
7. Docs: `docs/design.md` gains the designer conventions; README roadmap.

## Judgement calls already made

- No new dependency for drag/drop: pointer events on the existing SVG/CSS page, as `PageView`
  is already absolute-positioned. Snapping math lives in `packages/layout/src/snap.ts` (pure,
  unit-tested).
- Custom pages survive "Re-layout" untouched; a "Reset page to template" action clears overrides.
- Print safety is advisory (badges), never a hard block, except that nothing may be placed
  fully outside the bleed box.

## Acceptance criteria (to be refined)

- Overrides round-trip through the API, render identically in the editor, PNG preview and PDF
  (pixel-compare one page in a Chromium test).
- All editor operations have pure-function tests; undo/redo restores exact state.
- The fake-Immich manual flow demonstrates move, resize, text box, snap and keyboard-only editing.
