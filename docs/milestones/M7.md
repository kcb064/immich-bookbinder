# M7: optional AI, pets, maps, polish

Goal: the remaining roadmap items that are each small and independent. Deliver them as separate
commits in the order below so any one can be skipped or shipped alone. Every AI feature is off by
default, uses the admin's own Claude API key, and sends thumbnails only.

Read `CLAUDE.md` first. Expand each item into the M4-style sections at the start of the work.

## Existing seams

- `SettingKeys.aiEnabled`, `aiApiKey` in `apps/server/src/settings.ts` (unused so far).
- Selection sources in `packages/shared/src/book.ts` (`SelectionSource` union) and
  `apps/server/src/immich/gather.ts`; the `smart` source already calls `/search/smart`.
- Chapter openers (`chapter-photo`/`chapter-title`) and the unused `map` template in
  `packages/layout/src/templates.ts`; `planChapters` in `packages/shared/src/chapters.ts`
  yields place keys and GPS clusters per chapter.
- Candidate clusters (near-duplicates) and reasons in the `candidates` table; the review page
  (`apps/web/src/pages/Review.tsx`) shows alternates.
- Captions: `packages/pages/src/captions.ts`; `bookMetaFor` for titles and dates.
- Themes: `packages/shared/src/theme.ts` (`warm-editorial`, `clean-gallery`).
- Templates `colophon` and `qr` exist; shares from M4 provide the link to encode.

## Items

1. **Pets as saved smart queries.** A `pet` source: `{ kind: 'pet', name, query, exampleAssetIds
   [] }` that unions `/search/smart` for `query` and, per example asset, `queryAssetId`
   similarity; a "Pets" section in Settings to save them; wizard support. No new Immich
   permission.
2. **Map pages.** Chapter openers get an optional map slot: an SVG drawn from the chapter's
   photo coordinates (points and a route line) over a plain graticule, no tiles and no network,
   so it renders identically in the PDF. Toggle per book (`rules.chapters` gains `map: boolean`).
3. **QR on the colophon.** Encode the M4 share URL with a small pure-TypeScript QR encoder
   (`packages/layout/src/qr.ts`, unit-tested against known vectors) into the `qr` template;
   the colophon shows the share link text beneath.
4. **Claude features** (all opt-in, key stored encrypted, `docs/ai.md` explains data flow):
   - Captions and chapter titles: `POST /api/books/:id/ai/captions` sends the picked photos'
     `thumbnail` JPEGs with date and place, asks for one-line captions and chapter titles, writes
     them as slot text only where the user has not typed anything. Model id from
     `packages/shared/src/ai.ts` (default the current Claude model at build time), configurable.
   - Best-of-burst: for each cluster with 3+ members, ask which frame is best and apply it as
     the cluster winner with a `reason.kind = 'ai'`; the review page shows it and one click reverts.
   - Foreword: optional title-page paragraph generated from the book's places and dates.
   Rate-limit to one job per book at a time; show token usage and estimated cost in the UI.
5. **Themes.** A third theme and per-book overrides for paper colour, caption font size and
   frame style; the viewer and PDF pick them up through `PageView`.
6. **Notifications.** Optional ntfy/Gotify/webhook URL in settings; fire on render done, order
   status change and selection run failure.

## Judgement calls already made

- No map tiles: offline SVG maps keep the container self-contained and the PDF deterministic.
- AI never sees originals or full-size previews; only Immich `thumbnail` size, and never without
  the toggle.
- Notifications are fire-and-forget with one retry; no queue table.

## Acceptance criteria (per item)

Each item ships with tests for its pure logic, a fake for any external call (a fake Claude
endpoint in `apps/server/src/test/`), docs, and a README roadmap update. The last commit flips the
README status from "early development" to "usable".
