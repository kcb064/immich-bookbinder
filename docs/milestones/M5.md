# M5: Lulu ordering

Goal: from a print-ready book (M4) the admin can get a live price, place a hardcover order with
Lulu's Print API in the sandbox and then in production, and follow its status, with payment
happening on lulu.com. Lulu fetches the PDFs itself over HTTPS, so the app also serves signed
public export URLs.

Read `CLAUDE.md` and `docs/lulu-setup.md` first. Lulu's contract is `specs/lulu-openapi.yml`;
the verified facts are in `CLAUDE.md` ("Verified external facts").

## Existing seams

- `SettingKeys.luluSandbox`, `luluClientKey`, `luluClientSecret` exist in
  `apps/server/src/settings.ts`; secrets are encrypted through `SettingsStore` like the Immich
  key. `SettingsView` in `packages/shared/src/api.ts` and the Settings page
  (`apps/web/src/pages/Settings.tsx`) show how the Immich block is done; mirror it.
- `Book.luluProduct` (`binding`, `paper`, `finish`, `quality`) and `luluPodPackageId(format,
  product)` in `packages/shared/src/format.ts`. `FORMAT_PRESETS[*].luluTrim`.
- Cover geometry `coverGeometry(..., override)` and cover render kind from M4; `renders.data`
  stores the geometry used. Print render: `RenderService.create(book, 'print')`, file under
  `DATA_DIR/exports`.
- Preflight from M4 (`GET /api/books/:id/preflight`).
- Public prefixes `/public/*` are outside the auth guard (`routes/public.ts`, `routes/static.ts`).
- `PUBLIC_URL` (env) and the `publicUrl` setting; `docs/deploy-dockge.md` explains the tunnel.
- Test pattern for external services: `apps/server/src/test/fake-immich.ts` (Fastify app,
  `startFakeImmich()` returns `{ url, close }`). Build `fake-lulu.ts` the same way.

## Deliverables

### 1. Lulu client (`apps/server/src/lulu/`)

- `client.ts`: OAuth2 client-credentials against
  `{base}/auth/realms/glasstree/protocol/openid-connect/token` (`Authorization: Basic
  base64(key:secret)`, `grant_type=client_credentials`), token cached until 60 s before expiry,
  base `https://api.sandbox.lulu.com` or `https://api.lulu.com` from the sandbox flag. Typed
  wrappers for: `POST /cover-dimensions/`, `POST /validate-interior/` + `GET
  /validate-interior/{id}/`, `POST /validate-cover/` + `GET /validate-cover/{id}/`, `POST
  /shipping-options/`, `POST /print-job-cost-calculations/`, `POST /print-jobs/`, `GET
  /print-jobs/{id}/`, `GET /print-jobs/{id}/status/`. Generate types from
  `specs/lulu-openapi.yml` with `openapi-typescript` (add a `generate:lulu` script; output
  gitignored like the Immich types) and call through `openapi-fetch` as the Immich client does.
- Errors: `LuluApiError { status, body }`; 401 on a call invalidates the cached token once and retries.
- `status.ts`: `POST /api/lulu/test` proves credentials (token + `GET /print-jobs/?page_size=1`)
  and reports sandbox/production.

### 2. Public export URLs

- Table `exports` (migration): `id`, `book_id`, `render_id`, `token` (unique), `md5`,
  `expires_at`, `created_at`, `downloads`. Route `GET /public/exports/:token.pdf` streams the
  render file with `Content-Type: application/pdf`, `Content-Length`, no auth, 410 after expiry,
  rate-limited. Tokens are created per order attempt and expire after 7 days.
- `POST /api/lulu/reachability` builds a tiny throwaway export and fetches it through
  `publicUrl` from the server itself; reports status, latency and whether the body was the PDF
  (a Cloudflare Access login page is the classic failure; detect HTML).

### 3. Cover dimensions from Lulu

- Before a cover render on a Lulu format, call `/cover-dimensions/` with `pod_package_id`,
  `interior_page_count`, `unit: 'pt'` and pass the result as `override` to `coverGeometry`
  (`source: 'lulu'`). Without credentials fall back to the estimate and add a render warning
  "Spine width estimated; connect Lulu for exact dimensions".

### 4. Orders

- Table `orders` (migration): `id`, `book_id`, `lulu_job_id` (nullable until created), `env`
  (`sandbox|production`), `status` (our enum below), `lulu_status`, `pod_package_id`,
  `page_count`, `quantity`, `shipping_level`, `shipping_address` (JSON), `contact_email`,
  `cost` (JSON: line items, shipping, taxes, total, currency), `interior_export_id`,
  `cover_export_id`, `validation` (JSON: interior/cover ids + results), `messages` (JSON array),
  `tracking` (JSON array of `{ carrier?, url }`), `external_id`, `created_at`, `updated_at`,
  `error`.
- Status machine (`OrderStatus` in `packages/shared/src/book.ts`): `draft` -> `validating` ->
  `quoted` -> `submitted` -> `unpaid` -> `in-production` -> `shipped`, plus `rejected`,
  `error`, `canceled`. `lulu_status` keeps Lulu's raw value (`CREATED, UNPAID,
  PAYMENT_IN_PROGRESS, PRODUCTION_DELAYED, PRODUCTION_READY, IN_PRODUCTION, SHIPPED, REJECTED,
  ERROR, CANCELED`).
- Service `apps/server/src/lulu/orders.ts`:
  - `prepare(book, input)`: requires preflight without errors and a done `print` and `cover`
    render newer than `book.updatedAt`; creates exports; runs both validations (poll every 3 s,
    max 5 min); on success requests shipping options and a cost calculation for the address and
    quantity -> status `quoted`, cost stored.
  - `submit(orderId)`: `POST /print-jobs/` with `contact_email`, `external_id = <bookId>:<orderId>`,
    `shipping_level`, `shipping_address`, one line item with `printable_normalization`
    (`interior.source_url` + `source_md5_sum`, `cover.source_url` + md5, `pod_package_id`),
    `title` = book title -> `submitted`, then poll.
  - `refresh(orderId)`: `GET /print-jobs/{id}/status/` mapped to our status; tracking URLs from
    `line_item_statuses[].messages.tracking_urls`. A background ticker refreshes active orders
    every 10 min while the process runs and on demand from the UI.
  - `cancel(orderId)`: allowed only while `unpaid` (Lulu cancels via status change; if the API
    refuses, mark `canceled` locally and tell the user to cancel on lulu.com).
- Routes (`/api/books/:id/orders`): list, `POST` prepare, `GET :oid`, `POST :oid/submit`,
  `POST :oid/refresh`, `POST :oid/cancel`. Address schema `ShippingAddress` (name, street1,
  street2?, city, state_code?, postcode, country_code (ISO 2), phone_number, email); the last used
  address is saved in settings (`lulu.lastAddress`, not secret).
- Book `status` moves to `ordered` when an order is submitted.

### 5. Web

- Settings: Lulu block (sandbox toggle, key, secret, Test, Clear) and a "Public URL check" button
  wired to reachability.
- BookDetail: "Order" card -> `/books/:id/order` page: product choices (binding, paper, finish,
  quality) with the resulting `pod_package_id`, quantity, address form, shipping level radio with
  prices, cost table, "Validate and quote" then "Place order", then a status timeline with the
  Lulu job id, a "Pay on lulu.com" link (`https://www.lulu.com/account/print-jobs/<id>` in
  production, the sandbox equivalent when sandboxed; verify the path against Lulu's docs and
  fall back to the account page) and tracking links. Orders list with refresh.

### 6. Documentation

- `docs/lulu-setup.md`: sandbox account, where keys come from, what "Test" checks, the cost

- `docs/deploy-dockge.md`: `/public/exports/*` must bypass Cloudflare Access and the WAF; the

- `docs/print-specs.md`: cover dimensions now come from Lulu when connected.

## Judgement calls already made

- Poll, no webhooks by default. `PRINT_JOB_STATUS_CHANGED` webhooks with `Lulu-HMAC-SHA256` can
  come later; polling every 10 min is enough for a personal server.
- One line item per order; gift copies to several addresses are a separate order each.
- The app never touches payment. Lulu jobs sit `UNPAID` until paid on lulu.com; the UI says so
  plainly and links out.
- Sandbox and production credentials are separate pairs in settings; the toggle picks which pair
  is used, and every order records its `env`.
- Export tokens are single-purpose and short-lived; the same render can have several exports.

## Out of scope

Multiple line items, webhooks, Blurb or other vendors, cover editing beyond M4, order history
import from Lulu.

## Acceptance criteria

1. With `fake-lulu` credentials the Settings test succeeds; with wrong ones it fails with Lulu's
   message.
2. `GET /public/exports/:token.pdf` streams the PDF without auth, 410 after expiry, 404 for an
   unknown token, and the md5 in `exports` matches the file.
3. A prepared order on the fake Lulu goes `draft -> validating -> quoted` with a cost table;
   validation failures surface as `rejected` with Lulu's messages.
4. Submit creates a fake print job, the order is `submitted`/`unpaid` with a job id; `refresh`
   follows the fake's status progression to `shipped` with a tracking URL.
5. Cover render with Lulu connected records `source: 'lulu'` and the size Lulu returned.
6. Reachability reports HTML-instead-of-PDF as a failure with a hint about Cloudflare Access.
7. `corepack pnpm check` green; `fake-lulu.ts` covers every endpoint the client calls.

## Verification

```sh
corepack pnpm check
corepack pnpm --filter @bookbinder/server exec vitest run src/lulu
```

Manual: run `fake-lulu` on a spare port, enter its URL as a dev-only base override
(`LULU_BASE_URL` env, documented as development-only), walk the order page end to end in the
browser pane, screenshot the status timeline. A real sandbox run needs Kevin's sandbox keys and is
reported as not done if they are absent.
